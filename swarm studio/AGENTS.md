# Working in Swarm Studio

- Verify chat, swarm configuration, live screens, and report delivery through the normal app before calling a QA change done.
- Use a separate local database and account for test runs. Keep service keys and generated data in ignored files.
- Reuse the existing chat, model, and UI primitives. Swarm orchestration belongs in the API.
- Keep app copy short and preserve the user's decision before a swarm starts.
- Format changes with Biome. Run focused tests and the relevant package type checks.
